# ABC477E - Wheel Distance

$N+1$頂点があります。$A_1,A_2,...,A_N$が与えられて、それぞれ$A_i$が頂点$i$と頂点$(i \mod N)+1$の辺である。それで、$B_1,B_2,...,B_N$が与えられ、それぞれ$B_i$が頂点$i$と頂点$N+1$の辺である。$Q$個のクエリで、頂点$A$と頂点$B$の最短距離を求めよ。

これ読めば、グラフの問題にみえると思いました。大学にいたときは、ある開始頂点からゴール頂点まで最短パスを求めたいなら、普通にA\*というアルゴリズム使うのですが、一つのクエリであったら十分に速いと思いますが、$Q\leq 10^5$のクエリであれば、TLEの可能性も非常に高そうです。それで、書いてみると、問題の名前通り、グラフだけではなく、周りの輪と中心のハブみたいなグラフです。

では、この問題には、どうやって、二つの頂点の最短距離を先に計算して、クエリを処理するときはただルックアップすれば済むという問題です。少し考えてみれば、二つの頂点$i$と$j$の最短パスは以下の三つのケースにわかれています、

1. 中心頂点を通る場合には、$D_1 = D(i,N+1) + D(j,N+1)$.
2. 中心頂点を通らない場合には、以下のようにまた二つのケースにわかれます。
   1. 周りを時計回りに行く場合、$D_2$と呼びます。
   2. 周りを反時計周りに行く場合、$D_3$と呼びます。

$A$から$B$までの最短距離は$D=\min(D_1,D_2,D_3)$ということになっています。これまではおそらくそなたも流れを把握できるようになりましたね。場合ずつに解けるのがいいです。

ほぼ半分の経路は中心頂点を通るので、まずは中心から他の全ての頂点に最短距離を求めます。Dijkstraこそがこの理由でデザインされたアルゴリズムです。それで、また一つのことが、周りの輪にはループしているので、$S$は周りの外周で、$D_2=S-D_3$です。
